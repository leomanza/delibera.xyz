Repo meta — how every claim here is checked

No keys in any of these commands. The verifiers are offline or read-only; the live rail needs a partner key, which never reaches the browser.

Commands

npm run judgethe 9-step sequence: the policy, the jury, the bite, the ratification, the payment, the capsule, the chain, the no-key scan
npm test21 passing — invariant tests: capsule determinism · tally + quorum · envelope unwrapping · result freshness · fixture shapes
npm run verify:capsuleoffline — re-derive every digest in capsule.json against the fixtures
npm run verify:teethe jurors' TEE proofs, verified with NEAR's official verifier (3/3 signatures, 3/3 Intel TDX quotes)
npm run verify:livethe live precedent: chain state + receipt + live memory + TEE proofs, in one command
npm run live:railthe policy rail, live: the agent tries to pay an un-listed destination and the API refuses it before dispatch
npm run live:testnetthe whole loop with real jurors (testnet; mainnet behind an explicit flag)

Surfaces

  • demo.html — the narrated run: policy → the 403 bite → the jury → the payment → the capsule.
  • verify.html — drag the capsule + the four fixtures, watch every digest re-derive in your browser.
  • /second-opinion/demo — the product's own live session UI (start the coordinator; see the README).

What is proven, and how

  • The guardrail biting — the Agent Connect API refused a live transfer to a destination outside the owner-signed whitelist: 403 policy_destination_denied, with the provider's own body and request_id. Nothing moved.
  • The jury — three real AI jurors, one dissent, settled on-chain as a proposal on coordinator.agents-coordinator.testnet. The committed hashes still equal the live bytes.
  • The reasoning is TEE-attested — each juror's reply carries a NEAR AI Cloud signature; the signing key is bound to Intel TDX hardware. The proof travels inside the sealed result, so the on-chain commitment covers it.
  • The reasoning stays sealed — only sha256(result) reaches the chain; the text lives in the deliberation store.

Honest status

  • The payment leg that follows the owner's signature is a captured receipt (2026-10-19, mainnet rail). The live legs are the refusal, the jury and the settlement.
  • The demo accounts hold NEAR but no USDC, so the agent cannot be funded for a live payment without a top-up — named here rather than papered over.
  • The vendor refusal is not repeatable on demand (the capture's budget is spent); the live refusal is captured against a destination that is not on the whitelist, which the policy forbids regardless of balance.
  • One earlier precedent (#76) settled a wrong tally — a parser bug in our own harness. It is disclosed in the receipt, and the fresh run (#80) is the reference.
